# 长驻浏览器 Agent：开源复用审查

审查日期：2026-09-11。范围为候选仓库 README、项目元数据和官方文档，不是完整源码审计，也没有在真实 BOSS 账号试用第三方框架。以下取舍是针对本项目的工程判断。

## 先明确目标

目标是有持久工作环境、定时任务、浏览器操作、个人记忆、人机交接和失败恢复的长驻助手，不是让 LLM 每一步都自由操作。当前继续保留 Codex 作为决策入口；下列组件不意味着必须更换模型提供方。

## 候选与取舍

| 项目 | 已查证能力 | 本项目可复用位置 | 代价与决定 |
| --- | --- | --- | --- |
| [agent-browser](https://github.com/vercel-labs/agent-browser)（Apache-2.0） | 浏览器 CLI、带元素引用的快照、CDP 连接现有浏览器 | 浏览器适配器、失败现场快照，供决策层读取 | 优先做隔离环境只读原型；不能同时与旧控制器争抢聊天页。安全功能需显式配置 |
| [Playwright](https://github.com/microsoft/playwright) | 动作前等待可见、稳定、可交互等条件 | 替换手写轮询/元素操作，复用追踪诊断 | 优先评估原生浏览器库路线；能等待按钮不代表能确认消息送达 |
| [Browser Use](https://github.com/browser-use/browser-use)（MIT） | 面向浏览器任务的 Agent 与浏览器控制 | 探索未知页面、页面观测和恢复模式 | 候选而非直接替换；完整 Agent 循环需验证模型接口、成本与业务约束兼容性 |
| [BullMQ](https://github.com/taskforcesh/bullmq)（MIT） | 任务失败重试、固定/指数退避 | 将联系人读取、回复、对账拆为独立持久任务 | 引入 Redis 与第二套任务状态；多账号/多 worker 时再评估，不与当前 SQLite 各自裁定发送状态 |
| [LangGraph.js](https://github.com/langchain-ai/langgraphjs)（MIT） | 检查点持久化、状态恢复 | 等待扫码、等待用户补资料、恢复到明确任务阶段 | 需要迁移状态模型；不能和现有 Harness 双重调度。现阶段不整体迁移 |
| [Temporal](https://github.com/temporalio/temporal) | 持久工作流、活动重试与恢复 | 跨机器长时间任务 | 单账号部署成本较高；其文档明确要求业务活动设计幂等，框架不解决 BOSS 发消息去重 |

依据：[Playwright 动作等待](https://playwright.dev/docs/actionability)、[BullMQ 重试](https://docs.bullmq.io/guide/retrying-failing-jobs)、[LangGraph 持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence)、[Temporal 幂等边界](https://docs.temporal.io/activity-definition)。许可证记录仅针对本次查看的仓库元数据，真正引入时仍需审查固定版本及其依赖、NOTICE 和再分发要求。

## 优先复用路线

1. 保留业务流程、Codex 决策入口与唯一账本，先建立 BrowserAdapter 的契约测试。
2. 在无登录态的测试浏览器中比较 agent-browser 与 Playwright：列表读取、动态 DOM、弹窗、标签页身份、断连恢复、超时取消。两者先选一种适配，不叠加控制同一页面。
3. 原型先只读取，不允许点击真实发送。通过后再迁移读取链路，发送链路最后迁移且必须保留发送前意图、发送后回执与未知结果隔离。
4. 多账号、多 worker 或复杂人机审批确有需要时，再选一种任务/状态框架迁移；不要同时堆 BullMQ、LangGraph 和 Temporal。

本轮没有安装这些依赖，也没有把浏览器凭证交给第三方云。当前修复使用本项目已有账本实现联系人级隔离与退避，是参考成熟机制，不宣称已经集成外部框架。

## 会遇到的实际问题

- **发送非幂等**：点击成功但保存回执前崩溃，自动重试会重复发。框架重放只能用于安全读取，未知发送先对账。
- **人工与机器争抢浏览器**：程序内互斥锁管不了用户的鼠标；发送前仍核对会话身份、历史和岗位。
- **页面变化**：元素引用、岗位列表和会话内容会过期；快照必须刷新，不能用旧坐标自动点击。
- **消息记忆失真**：人工发过消息后，本地计划可能过时；平台历史优先，摘要不能当作实时事实。
- **长期运行成本**：每轮重复传 JD/聊天会浪费额度；检查点应记录已完成阶段，不能无限重试模型。
- **无消息不等于失败**：没有合适岗位、没有新 HR 回复都正常；健康检查应看明确失败与积压，不应逼模型凑发送数量。
- **人机交接**：验证码、补充薪资/到岗信息需要可恢复的等待状态，不能悄悄标记为永久处理完毕。
- **隐私与供应链**：浏览器快照、追踪、Cookie 和日志包含私密信息；固定依赖版本、审查安装脚本，不运行来源不明的同名 Bot 安装包。
