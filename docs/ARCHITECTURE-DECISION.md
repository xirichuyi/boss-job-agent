# ADR 001：模块化单体与端口/适配器

状态：目标已确定，增量迁移中；不代表所有模块都已满足依赖边界。

## 依据与选择

- [Cockburn：Hexagonal Architecture 原文](https://alistair.cockburn.us/hexagonal-architecture)：让业务可由定时器、用户或测试驱动，通过接口隔离数据库和外部设备。重点是业务与技术边界，不是六个文件夹。
- [Fowler：Monolith First](https://martinfowler.com/bliki/MonolithFirst.html)：在边界尚未稳定时优先维护单体，避免过早引入分布式复杂度。

针对本项目的判断：一个账号、共享浏览器会话、单一账本，采用一个可部署的 TS 模块化单体。调度器确定流程，模型只给建议和正文，适配器执行，账本记录。无需引入微服务、消息集群或新的 Agent 框架来完成此次整理。

## 模块职责与目标依赖

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| domain | 状态、资格规则、发送决策校验、恢复判定 | 读配置文件、启动进程、数据库或浏览器访问 |
| application | 搜索/联系/回复/对账用例，通过接口使用外部能力 | 页面选择器、CDP、SQL、模型命令行细节 |
| adapters/browser、model、telegram | 协议转换、外部交互、结果归一化 | 擅自调度新周期、改变额度、防重规则 |
| storage | 账本事务、持久化、备份能力 | 决定联系谁或发送什么 |
| config | 配置解析、默认值、校验 | 发消息、执行求职任务 |
| runtime | 进程监督、互斥、健康检查、依赖装配 | JD 匹配或生成聊天正文 |
| scripts | CLI 参数与启动入口 | 新增复杂业务逻辑 |

目标引用方向：入口/装配层 → 用例与适配器；用例 → 业务规则与接口；适配器实现接口。接口按行为定义，不为每个函数创建一层包装。调用外部能力不等于业务代码要 import 具体实现。

业务边界为 search（发现岗位）、outreach（首次联系）、inbox（持续会话）、reconciliation（核对不明发送）。这些模块共享显式账本契约，不通过随意修改别人的状态字段通信。

## 已落地与迁移债务

- 已落地：TS 运行入口、SQLite 权威账本、并行工作流与聊天互斥、单联系人用例、资源注入、独立代码/数据根。
- 本次清理：domain 不再直接读取配置；应用层 job-policy 暂时负责绑定配置。
- 自动守卫：AST 检查 domain 导入和 browser 反向依赖，随 npm test/CI 运行。这不是全仓库循环依赖扫描，也不声称隔离所有运行时副作用。
- 尚待清理：application 中直接配置/文件/存储调用；模型决策调用留在 application；config/effective 仍依赖 runtime；scripts 中残留业务；可变账本宽类型；visible.ts 按读取/发送职责拆分。
- 尚待运维：原子发布、版本核对、安全回滚、真实浏览器故障演练。

## 修改约定

1. 每次只移动一条业务链，保留原有对外行为和防重语义，先补回归再切换。
2. 用户偏好和运行预算归配置；协议常量与安全不变量留代码。配置变更必须校验并可查询实际生效值。
3. 新模块不得引入跨层反向依赖。现有迁移债务写明，不新增通用 utils 大杂烩或无职责的 manager。
4. 发送前意图持久化、未知结果隔离、人工消息优先是跨所有重构的验收条件。
5. 单元测试、隔离安装验收、真实平台验证分别报告；禁止用离线通过代替真实送达证据。
